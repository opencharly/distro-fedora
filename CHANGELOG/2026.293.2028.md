# 2026.293.2028 — chore(openwebui): advance the candy pin and give the box the witness it was missing

## Summary

`box/openwebui` pinned `pod-openwebui:v2026.274.0629`, so **every build of this box kept
shipping open-webui 0.9.5** — with the pre-fix entrypoint, i.e. no `--port` hand-off and
the MCP `info.id` identity collapse — even after the candy itself moved to 0.12.3
(opencharly/pod-openwebui#12) and its python layer pin passed the floor-check fix
(opencharly/pod-openwebui#14). The pin advances to `v2026.293.1944`.

The box also gains the check bed it never had. Every other consumer image in this repo is
witnessed by a disposable `check-*-pod`; this box was proven only by the transitively
composed candy checks, which by construction cannot see the *composition* — that is how a
stale pin survived three candy releases. `check-openwebui-pod` is that missing witness.

```yaml
check-openwebui-pod:
    pod:
        image: openwebui
        disposable: true
        lifecycle: dev
        env:
            OPENAI_API_BASE_URL: https://api.openai.com/v1
            OPENAI_API_KEY: not-a-real-key          # no live provider is contacted
            WEBUI_ADMIN_EMAIL: admin@openwebui.example
```

It carries no host-port pin, so concurrent runs cannot collide with a production deploy of
the same image. That claim is not an assumption: the engine injects `HOST_PORT` for the bed,
and the runs above show the probes hitting the ALLOCATED ports (earlier cold-boot failures on
this bed read `Get "http://127.0.0.1:33831/"` and `…:43653`, never `:8080`), which is why both
the candy's own probe and this new one use the same `${HOST_PORT:8080}` construct — the `:8080`
default is inert under the bed and only applies if the candy is checked outside one.

One assertion in it is the point of the whole PR: the bed reads the version from the app's
own `/api/config` and matches it, so "the box now ships 0.12.3" is proven **in-tree** by the
served build rather than inherited from the candy's release notes. The box owns the pin, so
it owns that expectation, and the two move together from here on.

```
      read from its own /api/config                                                 [openwebui-served-version]  status=200
```

The `attempts=` counter on the HTTP line exists only because the candy's HTTP probe now waits for first boot
(`eventually: 3m`), which is `pod-openwebui:v2026.293.1944` — so the deployed image is
provably the newly pinned candy and not a stale local build. The floor assertion passing
at 3.12 is the same evidence for the python layer.

The last line is the one that closes this PR's central claim: it reads the version from the
app's own `/api/config`, so it is the **served** build and not the pixi lock, and it is
asserted **in-tree** rather than inherited from pod-openwebui#12. The box owns the pin, so it
owns this expectation — when the pin advances, this line advances with it in the same change.
That is deliberately the opposite rule from a shared layer, which must never assert a
consumer's version (the lesson of opencharly/layer-python#8).

- **R1 — RCA every anomaly.** The stale pin was measured, not assumed: a build of this box
  carries `pod-openwebui v2026.274.0629` in its own `candy_version` label while `main` had
  already moved to 0.12.3. The reason nothing caught it is structural and now fixed — every
  other consumer image in this repo has a bed, and this one did not.
- **R2 — finish the cutover.** Pin and witness land together; the box's stale comment
  ("no box-level check") now points at the bed instead of asserting there is none.
- **R3 — no duplication.** The bed declares no checks of its own — it runs the composed
  candies' check set on a real deployment, which is the whole point of the pattern.
- **R4 — no workarounds.** No port pin, no sleep: readiness is the engine's bounded
  `eventually` primitive, inherited from the candy.
- **R5 — no legacy.** The old pin is replaced, and the comment that claimed no witness
  existed is corrected in the same change.
- **R7 — prove behaviour.** The full bed, including the destroy-and-rebuild leg.
- **R8 — emitted artifacts.** The claims are read from the run's own step report: the pin by
  the `attempts=` line naming `pod-openwebui:2`, and the served version by `[openwebui-served-version]`.
- **R9 — binary equals source.** `charly` 2026.293.1538, built from `charly` `origin/main`.
- **R10 — fresh disposable proof.** The disposable bed PASSED end to end on the final tree.
