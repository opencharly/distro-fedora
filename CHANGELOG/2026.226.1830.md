# 2026.226.1830 — re-stamp the schema version for the remove-candy-localpkg cutover

Four coupled edits in `charly.yml`, all required by the cross-repo
`remove-candy-localpkg` cutover (consuming spec `4cff4d0`).

- **The schema stamp.** `version:` → 2026.225.1508, keeping this repo's schema
  marker aligned with the landed spec so the load-time gate accepts it under
  the post-removal schema.
- **The `check-fedora-vm` bed rewrite.** Not incidental: the old bed asserted
  `rpm -q opencharly`, which is impossible once the cutover removes the
  localpkg package install, so a stamp-only change would leave a bed that
  cannot pass. `localpkg-rpm-autoresolve` (marker
  `LOCALPKG-RPM-AUTORESOLVE-OK`) becomes `charly-binary-installed`
  (`CHARLY-BINARY-OK`), `welded-command-project-less` drops the
  `/usr/lib/charly/plugins/*` file tests — the welded plugins are compiled into
  the binary, not baked beside a package — and moves its assertion target from
  `grep -q 'Container Engine'` to `grep -q 'Summary:'`.
- **The `fedora-vm` substrate comment**, rewritten from the localpkg
  auto-resolve description to the copy-step mechanism.
- **The `check-charly-fedora-pod` description**, dropping the clause
  "(no localpkg, unlike check-fedora-vm)" — it contrasted this pod against a
  localpkg path that no longer exists, so leaving it would be a stale
  reference (R5).

Every assertion is anchored on the MECHANISM rather than on charly merely being
reachable. The deploy stages its OWN host binary at a versioned `/tmp` path for
deploy use (`spec/exec/charly_install.go`, which never alters PATH), so an
unanchored `command -v charly` passes even when the candy installed nothing —
it cannot discriminate the install mechanism the step names. `test -x
/usr/bin/charly` can only be satisfied by the candy's `copy:` step, and the
`welded-command-project-less` probe runs `/usr/bin/charly doctor` — the
installed binary, not whatever `charly` resolves to on PATH. The
`Summary:` target is a strengthening for the same reason: a section header
prints early in a `charly doctor` run, whereas `Summary:` prints only once the
project-less dispatch has completed.

The `add_candy` pin is repointed from the immutable pre-cutover tag
`v2026.201.0706` (whose charly candy carries the removed `localpkg:` map and no
`copy:` step — the bed's checks would have passed via the exact mechanism the
cutover deleted) to `v2026.226.1719`, a post-cutover tag whose charly candy
lands the binary at `/usr/bin/charly` via its `copy:` step.

The dropped `rpm -q podman` / `libvirt` / `gocryptfs` / `tailscale` assertions
are a deliberate, disclosed reduction: they witnessed dnf auto-resolving the
`opencharly` rpm's `Requires`, a mechanism this cutover removes. The charly
candy's `distro:` section scopes tailscale to the deb-family (it is not in
Debian main, so the candy supplies it via the tailscale apt repo); on fedora,
tailscale came from the removed native package's deps, so the post-cutover
deploy does not install it and no assertion can pass. The debian/ubuntu sibling
beds keep their `tailscale-package-installed` check, which the candy's
deb-family package section does satisfy.
