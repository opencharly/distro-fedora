# 2026.232.1612 — reconcile the PR body when the CHANGELOG is finalized at merge

The 9th defect, observed live on the first canary live-proof PR (#24): when the
auto-merge finalization renames the PR's CHANGELOG placeholder to the merge-time
CalVer, the re-run validator re-reviews the FINALIZED head against the PR body.
A body that still names the author's placeholder (e.g. `CHANGELOG/2026.232.0004.md`)
reads as a description↔code mismatch (A1), the re-validation concludes `failure`,
and the run fails loudly — the mandatory post-finalize re-validation can never
pass on a PR whose body pins its placeholder.

The fix: the finalize step now reconciles the PR body BEFORE the re-run, by
appending an idempotent `## Auto-merge finalization` note naming the actual
(finalized) file. Idempotence: the marker prevents re-appending across re-runs.
Failure of the body-append is non-fatal — if the author's body pinned the
placeholder, the re-run validator blocks and the run fails loudly, leaving the
PR open for investigation (no merge with an unresolved mismatch).

The stub-gh harness now carries a faithful A1 model: the re-run validator's
check-run concludes `failure` on a finalized head (a sha ≠ the original head,
which was already validator-green) unless the body-append landed. All 19
decision paths / 73 assertions pass (S15: body-append resolves A1 → merge + tag;
S16: body-append fails → loud fail, exit 1, no merge).

## Change class

**ci/config** — a workflow file + its CHANGELOG entry. The R10 for a workflow
change is the live run of the workflow itself, which can only happen after this
lands on `main`; the stub-gh proof is the pre-landing gate.
