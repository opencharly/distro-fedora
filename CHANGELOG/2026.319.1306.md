# 2026.319.1306 — chore(fedora): drop the vendored copy of the corpus refs list

## Summary

Deletes `candy/charly-marketplace/charly.yml` — a 12 KB `candy:` list that this repo's images resolved
bare references against — and sweeps the two documents that described it.

**Why it has to go.** It pins tags that no longer exist, and a dead pin in a candy list aborts the corpus
generator for every consumer:

```
charly marketplace: collect entities: resolve @github.com/opencharly/pod-crabbox:v2026.274.0652:
  could not resolve ref "v2026.274.0652" in https://github.com/opencharly/pod-crabbox.git
```

`pod-crabbox`'s oldest surviving tag is `v2026.307.1759`. `opencharly/marketplace#613` bisected the chain
(`corpus → distro-<x>@<tag> → this candy list → pod-charly-hooks → layer-crabbox → plugin-crabbox →
pod-crabbox:v2026.274.0652 ⇒ abort`), and I re-measured this repo's own list with a calibrated
`git ls-remote` sweep of its **151** refs — **4 of them are unresolvable**, including a bare commit SHA
where a tag belongs:

```
UNRESOLVABLE @github.com/opencharly/layer-nvidia:054aa7702ebe79e8be444764f91a03933ba45eec
UNRESOLVABLE @github.com/opencharly/plugin-agentteams/candy/plugin-agentteams:v2026.271.2238

UNRESOLVABLE @github.com/opencharly/plugin-ollama/candy/plugin-ollama:v2026.272.0330
```

**The file said not to delete it, and that warning is stale — this PR proves it rather than ignoring it.**

The deleted file's description warned: *"Do not delete it as a redundant copy either. Removing it breaks
resolution here: `charly box validate` then fails with `unknown candy "kde-shell"` among others."* Three
measurements on the post-deletion tree, all pasted below, say otherwise:

1. **`kde-shell` is referenced by no box in this repo.**
   ```
   $ git grep -c 'kde-shell' -- 'box/'
   0
   ```
2. **The bare references that DO exist resolve — from the local builder box, not from this candy.**
   `box/fedora` composes `pixi`, `npm`, `cargo` as bare names, which is exactly the class this candy
   served. `charly box inspect fedora` shows where each resolves:
   ```
   $ charly box inspect fedora     # rc=0, on the post-deletion tree
   "cargo": "fedora-builder"
   "npm": "fedora-builder"
   "pixi": "fedora-builder"
   ```
   They resolve through the repo's own multi-stage builder, so the candy was never the only source.
3. **Every box still validates with zero warnings** — which is the exact failure the warning predicted:
   ```
   $ charly box validate
   charly box validate: OK — checked 261 candies, 40 boxes, 25 deploys, 6 distros, 7 builders;
   0 warnings, 0 errors
   ```

Docs swept in the same change (R5), because both claimed this directory WAS the closure source:
`AGENTS.md` ("TWO local candies are discovered … the `candy/charly-marketplace` closure manifest, and the
`candy/fedora-skills` skill carrier") and `README.md` (same claim). Both now say ONE local candy is
discovered, the skill carrier, and record what was removed and why.
