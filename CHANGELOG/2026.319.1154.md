Bumps the `nvidia` base's pins and gives that base the gate it never had, closing #110.

**Two pins move, not one.** `layer-cuda` goes `v2026.290.1513` → `v2026.314.0705` (the fix), and
`layer-nvidia` goes `054aa770…` → `7766a9d0…` because **the fixed cuda tag itself requires the newer
nvidia layer** — and two differing pins of one repo in one scope is a load error
(`charly box validate`: "resolved to multiple git tags with differing content within one scope").
Both are base-pin moves with the same rationale, and they must land together.

The pinned layer still listed **`cuda-cccl-devel`**, which no enabled repo provides, so the base's dnf
transaction failed and **every GPU image composing it was unbuildable**:

```
#18 5.991 Failed to resolve the transaction:
#18 5.991 No match for argument: cuda-cccl-devel
charly: error: command "build": … exit status 1
```

`v2026.314.0705` carries the fix — the header set resolves as `cccl-devel` from fedora-multimedia
(measured in the layer's own note: `fedora-multimedia -> cccl-devel-1:13.3.4.2.1-1.fc43`; the NVIDIA
`cuda-fedora43` repo also ships `cuda-cccl-13-2-0` but its gpgcheck fails, so that is not the source).

## RCA

- **Mechanism**: a base image's toolchain pin is only exercised when someone builds an image on it, so a
  stale pin can sit green in review and red in reality. The package list changed upstream
  (`cuda-cccl-devel` → `cccl-devel`); the layer was fixed (opencharly/layer-cuda#7) but the pin here was
  never advanced, so this repo kept consuming the broken list.
- **Missed control**: nothing in this repo builds its own bases on a schedule, and no bed covers the
  `nvidia` image itself — the defect surfaced only when an unrelated feature (the Qwen3-TTS provider)
  tried to base on it. That is the same class as #111: a claim (the base builds) with no gate behind it.
- **Blast radius**: every GPU image — `comfyui`, `immich-ml`, `jupyter-ml`, `ollama-cuda`, `python-ml`,
  `sway-browser-vnc` — inherits the failed transaction. Anything needing a GPU image had to bypass
  `nvidia` entirely in the meantime.
- **Root fix**: advance the pin (this PR). The durable control worth adding is a build-only check on
  each base so a stale toolchain pin fails here rather than in a consumer's feature branch.

## Change classification

**Breaking change + rollback:** the base every GPU image is built on moves, so a downstream GPU image
must be rebuilt to pick up the working toolchain — an image built from the previous base will not exist
after the bump, and its consumers rebuild on their next `charly update`. Rollback is a one-line revert of
the pin; no data, schema, or deploy state depends on it, because the pin is a build input only.
