### 2. Full validation — the gate the sweep does NOT cover

`box list candies` is a resolution probe, not full validation, so it is reported separately
rather than conflated. `charly box validate`, same binary, branch vs `origin/main`:

```
$ git checkout origin/main && charly box validate | grep -cE 'unknown candy|conflict'
61
$ git checkout feat/distro-sweep && charly box validate | grep -cE 'unknown candy|conflict'
5
```

**61 → 5.** The five that remain, verbatim:

```
box "chrome-headless": candy resolution error: unknown candy "chrome-devtools-mcp"
box "sway-browser-vnc": candy resolution error: unknown candy "chrome-devtools-mcp"

candy "github.com/opencharly/pod-chrome-cdp" depends: unknown candy "plugin-cdp"
```

They are **pre-existing and not fixed here** — `chrome-devtools-mcp` errors are present on
`main` too. Cause, traced: `pod-chrome-cdp@v2026.235.2110` reaches this graph transitively and
still uses the pre-cutover **bare** names:

```
$ grep -nE '^\s+- (chrome-devtools-mcp|plugin-cdp)\s*$' <cache>/pod-chrome-cdp@v2026.235.2110/charly.yml
26:            - plugin-cdp
```

Upstream already fixed it — `pod-chrome-cdp@v2026.240.1559` pins
`'@github.com/opencharly/pod-chrome-devtools-mcp:v2026.239.1557'` — but the stale one arrives
through another repo's pin, so it cannot be corrected from here. It stays an open member of the
post-cutover plugin-candy pin reconciliation batch.

### 3. The new `candy/charly-marketplace/charly.yml` — all 168 refs resolve

The previous body's R7 row said this file's plan check was "pasted above" via
`charly marketplace generate --root . --out /tmp/mkt-plan-check`. **That command cannot run in
this repo at all** — the `marketplace` verb is served by a plugin that only resolves from a
project declaring it (the charly checkout), so it was never run here:

```
$ charly marketplace generate --root . --out /tmp/mkt-plan-check
charly: error: unexpected argument marketplace
exit=80
```

The runnable proof is `charly box validate`, which resolves every `@github` ref in the file. The
file carries **168** refs and validation reports **no** error naming it:

```
$ grep -c "@github" candy/charly-marketplace/charly.yml
168
$ charly box validate 2>&1 | grep -c 'charly-marketplace'
0
```

A count of zero only means something if it can be non-zero, so the same control as the sweep —
break one ref in that file, then restore it:

