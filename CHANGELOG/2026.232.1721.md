# 2026.232.1721 — make auto-merge idempotency state-based + fix the body-append marker collision

Two live-observed defects in the auto-merge workflow:

## 1. The idempotency check never fired (re-finalization loop, defect #7 recurring)

The finalize guard `git log --format=%s origin/<branch> | grep -q '^docs: finalize
CHANGELOG placeholder to'` **never evaluated true in the GitHub runner** — zero
green fires across all six live runs carrying it, including the one run where it
was required (PR #24: the 1553→1627 re-finalization, run 32392051963, re-creating
the exact re-finalization loop the check was designed to prevent). The same
command returns 0 deterministically in every local reproduction (multiple clones,
identical git 2.55.0, byte-exact subjects/patterns, full non-shallow clones). All
structural hypotheses (ref resolution, force-push, partial clone, CRLF,
SIGPIPE on a 2.9KB output) are ruled out with evidence; the residual cause is an
unobservable runner-environment interaction with that specific history-walk
pipeline.

The fix replaces the indirect proxy with a **state-based file-marker check**: the
finalize writes a machine-checkable `<!-- auto-merge-finalized: <stamp> -->`
marker into the renamed changelog, and the idempotency guard reads the head's
copy of the file (`git show <head>:<file>` — a single blob read, the same
`git show`/`git diff` blob channel that demonstrably works in the runner) and
skips when the marker is present. A blob read tests the actual invariant (the
file is already finalized) instead of a history-text proxy.

## 2. The body-append marker collision (PR #26, run 32392375687)

The finalize's body-reconciliation guard grepped the PR body for the finalization
note's `## …` **heading** — but a PR body describing the workflow can
legitimately name that heading in prose (the canary body-append PR did, in its
step 3), so the guard matched the author's own prose and **silently skipped the
append**. The re-run validator then reviewed the finalized head against a body
still naming the placeholder and blocked on the body↔diff mismatch (A1).

The fix greps for a marker that author prose cannot contain — the appended note's
own HTML comment `<!-- auto-merge-finalization-note: <stamp> -->` — so the append
always lands unless this run already appended it.

## Validation

The corrected run block was proven against the stub-gh harness (a stub `gh` +
a real local git repo) — 21 decision paths, 84 assertions, all passing,
including new S17 (marker-collision body-append) and S18 (idempotency skip with
no finalize commit, the healed-canary path).

This is the canary that live-proves the corrected workflow — a subsequent PR on
this repo must go green → auto-merge (finalize-with-marker + body-append) → tag
before the byte-identical change is propagated to the other opencharly repos.
