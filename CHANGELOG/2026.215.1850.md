# 2026.215.1850 — tutorial-shell: the documented example becomes a real, tested box

opencharly.ai now teaches from a box that exists. `tutorial-shell` is quoted end to end by the
site's quickstart and concepts curriculum, and `tutorial-shell-dev` keeps that quotation honest by
re-proving it on every acceptance run.

## What landed

| Entity | Where | What it is |
|---|---|---|
| `tutorial-shell` | `box/tutorial-shell/charly.yml` | a three-candy box on the bare Fedora base |
| `tutorial-shell-dev` | `charly.yml` | its `disposable: true` pod bed |

## Why three candies, and these three

The box is a teaching artifact, so each candy earns its place by demonstrating one distinct idea a
newcomer has to learn, and nothing else is added:

- **`ripgrep`** — a pure TOOL layer: packages and probes, no service.
- **`sshd`** — a SERVICE layer, and the canonical init-polymorphism example (one `service:` list
  carrying both a `use_packaged:` systemd form and a custom `exec:` supervisord form).
- **`supervisord`** — the container init that actually runs the service.

A tools-only box would have been smaller, but it could not be deployed as a pod at all — nothing
would keep it up — so the deploy half of the lesson would have had no honest demonstration. Adding
a service candy was the alternative to adding a `sleep infinity` fixture, which would have taught a
pattern nobody should copy.

## The box asserts what its candies cannot

Both of `tutorial-shell`'s own `check:` steps are CROSS-CANDY invariants:

- `tutorial-shell-composition` — `rg` and `sshd` are on PATH *together*. Neither composed candy can
  assert this: ripgrep's checks pass in any image containing ripgrep, sshd's in any image
  containing sshd. Only the composing box can prove they arrived in one image.
- `tutorial-shell-search-works` — the composed tool really searches on this base, rather than
  merely being present.

The bed adds the two claims only a live deployment settles: the service came up under supervisord,
and the tool is usable inside the running pod.

## Editing rule this creates

The site **excerpts** `box/tutorial-shell/charly.yml`; it does not paraphrase it. Editing the box is
therefore a documentation change too — re-read the pages that quote it and update them in the same
cutover. `/charly-distros:tutorial-shell` carries the rule.
