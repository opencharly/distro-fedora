# 2026.266.1317 — feat: remove the check-pod bed relocated to opencharly/plugin-pod

## Summary of changes

Remove the `check-pod` R10 bed from `distro-fedora/charly.yml` now that the bed + its fixture live in the plugin repo that owns the behaviour (**opencharly/plugin-pod#6**). This is the source-side half of that relocation.

- `charly.yml` — deletes the `check-pod:` bed entity (the duplicate that now lives in plugin-pod) and replaces it with a comment recording the relocation.
- **Scope discipline: `box/check-pod/` is KEPT.** The fixture image `check-pod` is the shared fixture for FOUR remaining beds in this repo — `check-addcandy-pod`, `check-stepkind-emit-pod`, `check-enc-pod`, `check-tunnel-pod` — all of which reference `image: check-pod`. Deleting the fixture would leave them failing at image-build with `unknown box "check-pod"` (proven below). This mirrors `distro-fedora#54`, which kept `web-vm` for `check-cross-vm-http` while removing the three preempt beds. A bed's `image:` is a same-project entity ref, so each project needs its own fixture until those four beds relocate to their own owners.

**WHY.** A check bed must live in the repo that owns the artifact it tests. The `check-pod` bed's subject is the pod runtime/mechanism `plugin-pod` implements (kind:pod lifecycle, supervisord keepalive, deploy-target rendering), so it belongs with the plugin — not with the distro whose base image the fixture happens to build on. A surviving duplicate bed is the R3/R5 violation the move eliminates.
