# 2026.323.1533 — chore(pins)!: drop the VM driver layer from the Fedora CDI pod base

## Summary

`box/nvidia-cdi` — the GPU POD base every Fedora GPU image composes — named `layer-nvidia` explicitly,
and the two-line comment above it stated the only reason it existed: `layer-cuda` required a matching
`layer-nvidia`, and two differing pins of one candy in one scope is a load error. `layer-cuda`
v2026.323.0252 (opencharly/layer-cuda#30) drops that require, so the echo outlived its cause — and it was
the one thing keeping this pod base on the VM contract: the image baked a driver user-space and
`nvidia-ctk`, the toolkit's `cuda-drop-driver-userspace` then deleted the `nvidia*` binaries, and
`layer-nvidia`'s baked plan steps (`nvidia-ctk` exists, `nvidia-ctk --version`) could never pass on the
image the base builds.

**v2026.323.1259** and `layer-cuda` v2026.321.1520 → **v2026.323.0252**, the tag v2026.323.1259 requires.
The composition is then `agent-forwarding` + `layer-cdi` + `layer-cuda` — the pod contract `layer-cdi`

## Change classification

`nvidia-cdi` is the base of four pod images in this repo, and none of them gets an image-baked driver any
more. The change is deliberately breaking for a pod image: a CDI pod must bake no driver user-space and
must not carry `nvidia-ctk`, and until this tree its toolkit dependency silently put the driver layer back.
The VM-side `layer-nvidia` pins elsewhere in the org are untouched — those boxes compose the driver
themselves, because a VM guest owns its kernel.

```console
$ git grep -n "base: nvidia-cdi" -- box/
box/comfyui-cdi/charly.yml:3:        base: nvidia-cdi
box/jupyter-ml-notebook-cdi/charly.yml:3:        base: nvidia-cdi
box/python-ml-cdi/charly.yml:7:        base: nvidia-cdi
box/unsloth-studio/charly.yml:3:        base: nvidia-cdi
$ git grep -n "base: comfyui-cdi\|base: jupyter-ml-notebook-cdi\|base: python-ml-cdi\|base: unsloth-studio" -- box/
$ echo $?
1
```

The second command exiting 1 is the check that no box composes any of those four in turn, so the consumer
set above is complete. `box/immich-ml-cdi` is NOT in it: it bases on `fedora` and pins its own
`layer-cuda` v2026.290.1513, which still requires `layer-nvidia` — that is the standalone item in #128,
unchanged here.

**Breaking change + rollback:** those four images lose an image-baked driver they should never have had; a
consumer that relied on one inside a CDI pod breaks by design and is served instead by the host's CDI
injection, or, for a VM, by `opencharly/vm-nvidia`. The `layer-cdi` and `layer-cuda` tags also move, so a
consumer that pinned either below v2026.323.1259 / v2026.323.0252 sees the newer toolkit. Nothing outside
this file changes, so rollback restores the `layer-nvidia` entry and the two previous pins — a
single-file revert.
