# 2026.286.1009 — fix(beds): mark the two deliberate host-side local drivers `host: local` (sdk#330)

## Summary

Two bed *definitions* in this repo declare a deploy-level `local:` member that is **host-rooted by construction** — the DRIVER must reach a subject from the host's own vantage, which a pod-venue driver cannot (its own netns) — and neither said so. The loader walks a deploy-level member as its OWN root, so without the marking, landing on the operator's workstation is silent. Both now carry it explicitly:

```diff
 check-cross-vm-http:
     host-driver-vm:
         local:
+            # Deploy-level sibling of the bed's VM venue, HOST-ROOTED by construction: the DRIVER
+            # must reach ${HOST:check-cross-vm-http:80}'s host-vantage ssh -L forward, which a pod
+            # driver cannot (its own netns). Marked `host: local` so the intent is explicit …
+            host: local
             from: check-cross-local-driver

 check-cross-local-http:
     host-driver:
         local:
+            # Deploy-level sibling of the bed's pod venue, HOST-ROOTED by construction …
+            host: local
             from: check-cross-local-driver
```
