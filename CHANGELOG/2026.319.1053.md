# 2026.319.1053 — feat(fedora): ship the whisper ASR image and its R10 beds, and pin openwebui forward

## Summary

Adds the Fedora image and the R10 beds for the speech-to-text lane that landed in
`opencharly/layer-whisper#10` (`v2026.318.2328`) and `opencharly/pod-openwebui#22`
(`v2026.319.0820`, since advanced to `v2026.319.0943` by #25).

- **`box/whisper/charly.yml`** — a new image whose entire content is
  `@github.com/opencharly/layer-whisper:v2026.318.2328` on the `fedora` base. No dbus, no charly CLI:
  the image exists to run one service.
- **`check-whisper-pod`** — the KEYLESS posture. Builds the image from the released tag, deploys it as
  a disposable pod, and runs the candy's own baked checks. It carries no `plan:` on purpose: every live
  claim here is the composed candy's check, so a bed plan could only duplicate it (R2).
- **`check-whisper-auth`** — the KEYED posture, which a baked check **cannot** assert (the default
  deployment is keyless, where a 401 would be wrong). A disposable pod deployed with
  `WHISPER_API_KEY` set asserts both directions: an unauthenticated request is refused, and the same
  request carrying the correct bearer is served the fixture's transcript.
- **`box/openwebui` pin → `v2026.319.0943`** (the newest consumer tag) **and the coupled assertion
  fixed**: the box OWNS the pin, so it owns the served-version expectation. It still asserted
  `"version":"0.12.3"` while the pin had already moved past it — a red bed waiting to happen, and the
  finding filed as `#101`. Bumping the pin without fixing the assertion would have landed that red.
- **No joint bed, deliberately.** A bed that drives the Open WebUI container through the whisper
  container **cannot currently be expressed**: three shapes were measured and each failed for its own
  reason — sibling member with container DNS (48 attempts, `exit=7`), sibling member with
  `${HOST:<bed>:<port>}` (host loopback, unreachable from inside a container), and nested containers
  where the `command:` verb **SIGSEGV'd** in `plugin-command`. Filed as **`opencharly/charly#1153`**
  with all three shapes and their evidence. Shipping a dead bed in its place would have been the fake
  fix: the integration is covered by the ASR beds, the consumer's committed projection stubs, and a
  live two-deployment run.

## Rulebook compliance

- **R0** — skills loaded before authoring: `image`, `layer`, `check`, `disposable`, `build`, `validate`,
  `deploy`, `git-workflow`, `strict-policy`, plus this repo's signpost `AGENTS.md`.
- **R1** — one finding is **fixed here** rather than filed forward: `#101`'s stale served-version
  assertion becomes blocking the moment this PR bumps the pin, so it is corrected in the same change
  (`grep -c '"version":"0.12.3"' charly.yml` → **0**). Two failures of my own joint-bed attempts were
  root-caused rather than retried: the auth mechanism (`WEBUI_ADMIN_PASSWORD` is a `secret_require`, so
  charly auto-generates the secret and a literal bed value can never authenticate) and the nested-step
  variable resolution (`${HOME}` is not auto-exported for an assert-only step; absolute path required).
  The remaining blocker is filed: `opencharly/charly#1153`.
- **R2** — one bed per posture, no duplicated assertion: `check-whisper-pod` has no plan of its own, and
  the auth assertions exist once, in the bed that can run them.
- **R3** — no sleep, no retry-on-flake: every wait is a bounded `eventually:` with a stated budget.
- **R4** — product before prose: pin, assertion and beds move together.
- **R5** — the retired claim (`0.12.3`) is swept in the same commit.
- **R6** — session worktree off fresh `origin/main`; no destructive git action; a bed held by another
  session was left alone.
- **R7** — the keyed bed asserts both directions, so the 401 arm fails if the forwarding branch is
  removed; the ASR beds assert the engine's behaviour, not a model name.
- **R8** — every bed ran live against real services; nothing mocked.
- **R9 / R10** — driven by the worktree-local CalVer binary; the beds are `disposable: true` deploys
  with a fresh rebuild and teardown, and their `summary.yml` is the record.

does not deploy it.
