# 2026.279.1511 — chore(gitignore): ignore the `image/` VM-build scratch dir

## Summary

`charly vm build` writes scratch to `<vm.image_dir>/<vm>/.build.lock`; the default
`vm.image_dir` is `image/`. **This PR changes exactly one file in `distro-fedora`** —
`distro-fedora/.gitignore`, adding `image/` under the existing "# VM / disk-image build
outputs" block (which already covers the sibling `output/`). `charly/.gitignore` and
`distro-omarchy/.gitignore` already ignore `image/`; the remaining `distro-*` repos are
fixed in their OWN PRs, tracked by opencharly/distro-cachyos#126:

- `opencharly/distro-arch#51`
- `opencharly/distro-debian#34`
- `opencharly/distro-ubuntu#34`
- `opencharly/distro-cachyos` (in its PR #125)
(Each of those is a SEPARATE PR; this PR changes only the two added lines in distro-fedora/.gitignore.)

## How tested

The changed artifact IS the ignore rule, and its behaviour is verified by the exact
command git itself uses to test it, run on THIS repo's worktree at the head of this PR:

```
$ cd distro-fedora && git check-ignore -v image/
.gitignore:11:image/	image/
$ grep -n '^image/' .gitignore
11:image/
```

Before the change the same query returned nothing — `git show origin/main:.gitignore | grep -c '^image/'` is `0` for this repo, so the path was untracked-but-visible. The gap was found when a `charly vm build` in a sibling repo left an untracked `image/` tree that `git status` reported as `?? image/`.

`git check-ignore` is the change-class gate for a `.gitignore` diff — it executes the
changed rule and returns non-zero when the path is NOT ignored. `charly box validate` is
unaffected: `.gitignore` is not a manifest input, and the repo's manifest validates
unchanged.
