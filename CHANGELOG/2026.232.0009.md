# 2026.232.0009 — live-proof the state-based idempotency + marker body-append end-to-end

PR #27 landed the two live-observed defect fixes on `distro-fedora` main:

1. **State-based idempotency** — the finalize step now writes a
   machine-checkable `<!-- auto-merge-finalized: <stamp> -->` marker into the
   renamed changelog, and the idempotency guard reads the head's copy of the
   file (a single blob read, no history walk) and skips when the marker is
   present.
2. **Marker body-append** — the finalize's PR-body reconciliation guard now
   greps the note's unique HTML-comment marker (which author prose cannot
   contain) instead of the note heading.

That logic was proven by the stub-gh harness (20 decision paths / 92
assertions), but it must ALSO be exercised by a live PR through the corrected
workflow — the stub is a model, the live run is the gate.

**This PR deliberately pins its own placeholder filename** — the Change class
below names `CHANGELOG/2026.232.0009.md`. The corrected workflow must now:

1. wait for every status check to be green,
2. finalize the placeholder to the merge-time CalVer (`git mv` + H1 rewrite,
   writing the `auto-merge-finalized` marker),
3. append the finalization note naming the actual finalized file (the marker
   guard must fire even though this body names the note heading in prose),
4. re-run the validator to green on the finalized head,
5. merge via GitHub auto-merge and mint `v<YYYY.DDD.HHMM>` on the merged HEAD.

The merge + tag of this PR is the recorded proof. Only when it lands AND its tag
