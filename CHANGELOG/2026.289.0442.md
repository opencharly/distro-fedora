### Round 1's BLOCK, and what this round's commit fixes

Round 1 returned a BLOCK with two findings, both R1. Both are fixed in the second commit
(`cfb21bd`); the move itself is untouched.

**1. A parking phrase with no filed issue (R1 / CONC(b)).** The body had recorded two programme
drifts — §6's W2 row counting `distro-ubuntu` at 5 where the tree measures 6, and W2 and W4 both
claiming the five `distro-*` repos — as *"already on the record in the plan's own drift report #3"*,
while also claiming nothing needed filing. A named drift report is not a filed issue, and R1's
fix-it-or-file-it allows no such split. **Filed: `opencharly/opencharly#503`**, carrying both drifts
with the per-repo measurement. The plan could not simply be corrected here for two measured reasons:
it is a **gitignored working document** (`plan/*` — `.gitignore:17`, *"plans — working docs, never
committed"*), so it cannot carry a durable, linkable record; and the ledger's own protocol keeps §6
as written (*"a plan corrected in place destroys the evidence that it was wrong"*), which is why the
drift lives in a dated report. The issue is the fix for the part that report cannot do.

**2. A skill file that contradicted itself (R1 / CONC(c)).** `.agents/skills/fedora-test/SKILL.md`
said *"Currently disabled"* in its frontmatter while its own Box Properties table said
`| Status | enabled |`. The contradiction pre-dated this PR — it was in `origin/main`'s node, between
the node's `description:` and its `content:`, and this PR carried it byte-for-byte into the file —
which is the honest reason a byte-identity proof could not catch it, and also why the fix belongs
here: this repo is the source the projection is generated from.
