# 2026.229.1232 — the check-ollama-pod bed, and it declares no plan of its own

Adds the disposable `check-ollama-pod` bed: a pod deploy of the `ollama` image that
proves the ollama candy, the CUDA backend, and the compiled-in `command:ollama` plugin
(opencharly/charly's `candy/plugin-ollama`) end to end.

**The bed carries no `plan:`.** Every step it needs is baked into the candies it
composes — the server probes (binary/file, `/api/tags` 200, `ollama --version`,
`ollama list`), the CUDA backend library probe from `ollama-cuda`, and the three
host-side `charly ollama` steps (help dispatch, live `version` round-trip, `list`)
that were authored on the `ollama` candy rather than here. An earlier draft of this bed
carried those three steps inline; moving them to the candy is what lets the CachyOS
sibling bed (`check-cachyos-ollama-pod`) prove the same surface without repeating a
line (R3), and it means any future box composing ollama inherits them for free.

The `ollama` box additionally composes `ollama-cuda`, so the bed asserts the CUDA
backend actually ships rather than assuming the base install provides it.

The heavy pull/persist proof stays with the candy's `agent-check:` (graded by
`charly check feature run`), keeping the deterministic bed light.

## Also — a stale claim in the bed header

The comment introducing this file's bed block claimed "Ports remapped into the 4xxxx
range so a bed run never collides with a production deploy of the same image". No bed
in this file pins a host port and none has for some time — every inherited container
port auto-allocates a free 127.0.0.1 host port, which is both why concurrent bed runs
cannot collide and why plan steps reach the port through `${HOST_PORT:N}`. The same
file already said so 220 lines further down, next to `check-enc-port-pod`. The header
now matches the mechanism.

## Also — a test-bed credential store for the enc beds

A committed `.env` (`GOCRYPTFS_PASSWORD=charly-bed`) serves as the credential store for the
encrypted-volume (gocryptfs) check beds. The passphrase is a deliberately-committed test-bed
credential, not a production secret: the enc beds' `ExecStartPre` `charly config mount` resolves
it from the charly credential store under systemd, so the beds run unattended on a fresh host
without operator secret setup.

## Also — adopt charly v2026.231.0714

Every `@github.com/opencharly/charly/candy/...` pin in this repo moves from
`v2026.227.0914` to `v2026.231.0714` (159 pins across 38 files). This is a pure
version adoption: the candies themselves are unchanged, only the tag they are fetched
at.

The adoption is required by the ollama cutover's consumer landing. `v2026.231.0714`
is the charly tag that first ships `candy/ollama-cuda` and `candy/ollama-rocm` — the
split GPU backends this repo's `check-ollama-pod` bed composes — and it also carries
the chrome candy fix (`--setopt=tsflags=noscripts` for `google-chrome-stable`'s `%post`
scriptlet, which raced dnf's transaction lock and failed the `check-cross-pod-cdp`
bed's `image-build-chrome` step). The authoritative gate is this repo's full bed
roster against the adopted tag (B6 step 4): the consumer's image R10 proves the
composition the pins feed.
