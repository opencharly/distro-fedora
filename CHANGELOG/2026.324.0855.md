# 2026.324.0855 — feat(immich)!: delete the Fedora immich and immich-ml-cdi boxes

## Summary

**Deletes the two Fedora Immich boxes — `box/immich` and `box/immich-ml-cdi` — that the one-image Immich v3 cutover supersedes, and the prose that pointed at them.**

The producer is `opencharly/pod-immich#13` ("build Immich v3.4.1 and carry the ML backend in the image", merged 2026-11-16): the server, the web UI and the machine-learning backend (port `3003`) are now ONE candy in ONE image. The CachyOS GPU stack adopted it as `box/immich-cdi` + the `check-cachyos-immich-pod` bed (sibling leg, `opencharly/distro-cachyos`). Once the ML backend lives in the single image, the Fedora pair is dead weight: a CPU `immich` box and a separate `immich-ml-cdi` box that composes the retired `pod-immich-ml:v2026.274.0811`.

Six files, 13 insertions / 53 deletions:

- `box/immich/charly.yml` — deleted (13 lines).
- `box/immich-ml-cdi/charly.yml` — deleted (32 lines; it pinned `pod-immich-ml`, the repo the one-image cutover retired).
- `AGENTS.md` and `README.md` — the box lists no longer name the two deleted boxes.
- `.agents/skills/fedora-nonfree/SKILL.md` — three edits, not just a name removal: (a) the frontmatter `description:` drops "like immich" and now names what the base actually serves (the GPU base box `nvidia-cdi`, plus the `fedora-rpmfusion` / `fedora-builder` images); (b) the consumer paragraph drops `/charly-immich:immich` and names the same three; (c) the "Derived Boxes" list, which previously held only the deleted `/charly-immich:immich`, now lists the GPU base's skill `/charly-distros:nvidia` (stating that the BOX it documents is `box/nvidia-cdi`), `fedora-rpmfusion`, and `/charly-distros:fedora-builder`. The skill-vs-box distinction is written out because round 1 showed the two vocabularies read as one.
- `box/fedora-nonfree/charly.yml` — the one comment that used `immich` as the example now uses `fedora-rpmfusion`, a base that does exist.

The replay dropped main's newer edits to `box/immich-ml-cdi` (PR #131's driver-layer pin fix) **because the file is deleted here**: that fix has no object to live in, and its purpose — keeping a still-shipping box's pins current — is moot for a box this change removes.
