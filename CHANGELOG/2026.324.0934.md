# 2026.324.0934 — chore(pins): move the CDI pod base to the layout-scoped producer

## Summary

Two producer refs in `box/nvidia-cdi/charly.yml` move in ONE edit: `layer-cdi` `v2026.323.1259` → **`v2026.323.1618`**, and `layer-cuda` `v2026.323.0252` → **`v2026.323.1604`**.

`layer-cdi` `v2026.323.1618` is the layout-scoped producer release — its build-time assertion `cdi-no-baked-driver-libs` derives its `drv=` predicate from the producer's ONE definition instead of a hand-copied pattern — and it `require:`s `layer-cuda` `v2026.323.1604`, the release whose strip walks `/usr/lib`, `/usr/lib32` and `/usr/lib64` for the driver libraries AND for the `nvidia` / `vdpau` / xorg trees (opencharly/layer-cuda#28, opencharly/layer-cdi#12). This is the Fedora venue, where `/usr/lib64` is a REAL directory rather than the symlink it is on Arch/CachyOS, so the layout the older pair could not reach is exactly the one that matters here.

Both refs move in one edit because the pair is one contract: `layer-cdi`'s own `require:` names the `layer-cuda` tag, and two differing tags of one candy inside one box scope is a load error — pinning only `layer-cuda` would leave `layer-cdi`'s requirement as the second tag in `box=nvidia-cdi`.
