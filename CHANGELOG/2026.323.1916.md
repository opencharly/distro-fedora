# 2026.323.1916 — chore(boxes)!: drop the VM driver layer from the two remaining Fedora pods

## Summary

Two POD images in this repo still composed the VM driver layer; neither does now.

- **`box/charly-fedora`** pinned `layer-nvidia:054aa7702ebe79e8be444764f91a03933ba45eec`
  directly. That entry is deleted. The image is deployed as a pod (`check-charly-fedora-pod`),
  so the kernel module is host-global and the driver user-space arrives per container
  through the host's CDI spec — the image must bake none.
- **`box/immich-ml-cdi`** pinned `layer-cuda:v2026.290.1513`, a release that still
  carries `require: layer-nvidia`, so the pod composed the driver transitively and
  nothing removed what it installed. It now composes the CDI contract and the
  driver-free toolkit: `layer-cdi:v2026.323.1259` +`layer-cuda:v2026.323.0252`
  (the release that DROPPED the require, layer-cuda#30) + `layer-python-ml:v2026.323.1851`
  (whose own `require:` names exactly that toolkit — opencharly/layer-python-ml#14).
  The `cdi-no-baked-driver-libs` build assertion is now composed, so a regression
  fails the build instead of shipping.

Two prose surfaces claimed a driver/GPU layer neither image carries, and both are
corrected in the same cutover: the `check-charly-fedora-pod` description
("… + nvidia-cdi") and `.agents/skills/charly-fedora/SKILL.md` (the nvidia candy in
the layer list, the GPU section, and the `which nvidia-ctk` probe). The skill is
authored here; the marketplace corpus is a projection and is regenerated, never
hand-edited.

## Change classification

Both images lose an image-baked driver they should never have had, and
`immich-ml-cdi` also gains the CDI contract assertion. A consumer that relied on a
driver inside either pod breaks by design and is served instead by the host's CDI
injection, or, for a VM, by `opencharly/vm-nvidia`. `immich-ml-cdi`'s
`layer-python-ml` pin moves to `v2026.323.1851` so the toolkit cannot pull the
driver back.

**Breaking change + rollback:** a pod no longer carries `nvidia*` binaries or a
driver user-space; a workload that shelled out to `nvidia-ctk` inside the image
must use the host's tool, and a GPU workload must run with the CDI device. Roll back
by reverting the four files — the previous pins and prose return together.
